### 3. 为什么不用绝对路径

实测（Edge 真实窗口）：

| 方式 | 结果 |
|---|---|
| `file:///C:/.../soudpad%20音频.../星河追梦+(Beyond+the+Stars)-...mp3` | **ERR4**（源不支持） |
| 同目录相对路径 `./track.mp3` | **OK，时长 217s** |

绝对路径里的中文+空格+括号组合会让 media 加载器判定源不支持，相对路径稳。
所以把音乐以 `track.mp3` 放在 HTML 旁边，改名/换歌只需替换这个文件。

（排查时还踩了一个坑：探测窗口如果在屏幕外，Edge 会**推迟媒体加载**，看起来像“加载失败”，其实是窗口被遮挡。）

### 4. 替换默认音乐

把新歌重命名为 `track.mp3`，覆盖桌面上的那个即可。
不想动文件就用右下角「选曲」。

### 5. 已知限制

- 页面移动位置时，`track.mp3` 要跟着一起走
- 网页无法读任意本地路径（安全限制），所以「自选」只能通过文件选择器

# Stage 16 · 星空重做

## 1. 星点：亮度 / 色温 / 大小 / 星芒

每个星点由格点哈希决定：

| 属性 | 实现 |
|---|---|
| 亮度 | `mag = pow(hash, 3.2)` → 暗星远多于亮星（幂律，接近真实星等分布） |
| 色温 | 四段插值：蓝白(O/B) → 白(A) → 黄白(G) → 橙红(K/M) |
| 大小 | `mix(0.0011, 0.0030, mag)` → 亮星核更大 |
| 星芒 | 只有 `mag > 0.52` 的亮星有十字衍射芒 |

三层星场（scale 300 / 520 / 780）保证近处细密、远处疏朗。

## 2. 旋臂调制

```
armSig = galBand × (0.25 + 0.55·armA + 0.35·armB) × (0.50 + 0.60·wisp) + galBand·coreGal·0.45
dm     = 基准密度 × (1 + 3.0·armSig) × (1 − 0.80·lane)
```

- 银道带内星点密度 ×4，带外星点稀疏
- 螺旋臂周期项让带内也有疏密
- 尘埃带（lane）里星点减 80%，形成暗缝
- 银河乳光压到 0.055 并叠加 `fbm` 颗粒，避免糊成一片蓝光

## 3. 出现时机

星星乘 `smoothstep(0.35, 0.90, uNight)`：黄昏几乎看不见，真正入夜才铺满。

## 4. 踩过的坑

星场函数一开始插到了**体积光**的 shader 里（因为 `void main(){` 有多个），
导致天球 shader 引用未定义函数 → 天空全黑。已修正到天球 shader 内。

# Stage 18 · 银河层次 / 星点尺度 / 播放修正

## 1. 银河三层结构（按描述重建）

| 层 | 颜色 | 做法 |
|---|---|---|
| 中心条带 | 深紫黑 / 深蓝 | `coreB` 高斯，用 `mix` 把亮度压向 `vec3(0.028, 0.010, 0.052)`，强度 0.82 |
| 主带 | 亮白 | `midB` 高斯 × 旋臂周期项 × 颗粒噪声，0.155 |
| 外圈 | 淡橙红 | `haloB` 高斯 × 0.062，色 `vec3(0.88, 0.54, 0.38)` |
| 整体 | 淡淡光晕 | `exp(-(glat/0.62)²) × 0.020` |

尘埃带（lane）与中心暗带叠加，形成深紫黑的裂缝。

**顺手修的 bug**：银河噪声原本用 `glon` 直接采样，`atan` 在 ±π 处有接缝 →
天上一道硬直边。改成圆周坐标 `vec2(cos(glon), sin(glon))` 采样后消失。

## 2. 星点尺度（以月亮为基准）

- 月亮视直径 **0.52°（31′）**
- 改前星星尺寸 0.06°–0.26°（约月亮 1/2 ~ 1/8）→ 明显偏大
- 改后 **0.024°–0.06°**（约月亮 **1/9 ~ 1/22**）
- 亮度相应提高（0.25+2.6m → 0.55+3.4m）补偿变小后的可见度

## 3. 去掉十字星芒

星点、星座星的四芒全部移除，只保留高斯核。

## 4. 音乐暂停 bug

**现象**：点开始后无法暂停。
**原因**：全局「第一次手势自动播放」监听器挂在 window 上，
点暂停按钮后音频变成 paused，但任何后续点击（包括点画面转视角）
都会再次触发 `tryPlay()`。

**修法**：
- `started` 标志：只要播放过一次就永不再自动拉起
- 手势监听器忽略 `#music` 面板内的点击
- 播放按钮 `stopPropagation`

**验证**（CDP 真实鼠标事件）：

```
播放后   : paused=false, cur=4.0
点暂停后 : paused=true,  cur=4.0
再等 1.5s: paused=true,  cur=4.0
点画面后 : paused=true,  cur=4.0   ← 不会被重新拉起
```

# Stage 20 · 用参考照片做定量重建

## 1. 从照片里量出真实剖面

把参考图旋转 -37.1°（PCA 求得银道主轴角度）对齐，逐行统计亮度：

| d(px) | 实测亮度 | 高斯拟合 | 指数拟合 |
|---|---|---|---|
| 100 | 0.45 | 0.45 | 0.45 |
| 140 | 0.30 | 0.21 | 0.33 |
| 200 | 0.17 | 0.04 | **0.20** |
| 240 | 0.10 | 0.01 | **0.15** |

**结论：银河的横向亮度是指数衰减 `exp(-d/126)`，不是高斯。**

高斯尾巴掉太快 → 带边缘出现硬边 → 这就是「旋臂和周围夜空割裂」的根因。
指数长尾能自然融进夜空。

## 2. 按实测重建

```glsl
coreB = exp(-|glat| / 0.050);   // 亮核
mainB = exp(-|glat| / 0.170);   // 主带，e 折 ≈ 10°
haloB = exp(-|glat| / 0.420);   // 长尾外晕
```

颜色直接取自照片像素均值：
- 核心 `(93,78,74)` → `(1.00, 0.86, 0.80)` 暖白
- 外圈偏冷蓝紫 `(0.56, 0.60, 0.74)`
- 暗尘 `(0.035, 0.024, 0.019)` 深褐

去掉了原来那圈「橙红亮边」——那是 `rim` 项造成的上下两条亮线。

## 3. 颗粒感

在带内加了一层**超密集微星**（scale 1500、密度 0.030、尺寸 0.55×），
只出现在银道带里，把「奶油」变成「细砂」。

## 4. 割裂的另外两个来源也修了

- 星密度过渡 `smoothstep(0.015, 0.34)` → `smoothstep(0.010, 0.85)`（不再突变）
- 尘埃用两层各向异性噪声叠出条状分叉，不再是一整片暗块

# Stage 22 · 沿臂亮度曲线（星空收工）

## 1. 从照片提取沿臂亮度

- 在带心上下 ±30px 取平均亮度，得到沿带方向的一维剖面
- 15px 滑动平均去噪
- 5%/95% 分位归一化，重采样到 **512 点**
- 首尾各 64 点做**交叉淡化**，让曲线周期化（否则铺满 360° 会出现亮度跳变）
- 存成 512×1 PNG：**214 字节**，base64 不到 1KB

## 2. 接进着色器

```glsl
float armLum   = texture2D(tArmLum, vec2(glon * 0.15915 + 0.5, 0.5)).r;
float armShape = mix(0.55, 1.45, armLum);
float armW     = (0.42 + 0.30*armA + 0.18*armB + 0.10*armC) * armShape;
```

`glon/(2π)+0.5` 正好映射到 [0,1] 一个周期，接缝处连续。
armShape 同时调制**主带亮度**和**星点密度**——亮的段落星星也多，符合真实。

原先的数学旋臂项（armA/B/C）权重下调，因为沿臂变化现在由照片曲线主导。

## 3. 星空系统全貌（收工）

| 模块 | 做法 |
|---|---|
| 星点 | 4 层网格（300/520/780/1500），亮度 `pow(hash,3.2)` 幂律，色温四段，尺寸 0.024°–0.06°（月亮的 1/9–1/22） |
| 银河剖面 | `exp(-d/0.195)` 主带 + `exp(-d/0.49)` 外晕（实测拟合，非高斯） |
| 尘埃 | 照片提取的可平铺纹理（256²，内联 48KB）+ 噪声扰动 |
| 沿臂变化 | 照片提取的 1D 亮度曲线（512×1） |
| 配色 | 核心暖白 (1.00,0.86,0.80)、外圈冷蓝 (0.56,0.60,0.74)、暗尘深褐 (0.035,0.024,0.019) |
| 星座 | 25 颗真实赤经赤纬，无连线无标签 |
| 流星 | 仅夜间出现，小尺寸拖尾 |
| 视角 | 俯仰 ±89°，水平无限 |

性能：RTX 4050 / 1280×720 / **60 fps**。

# Stage 24 · 水膜层

## 1. 整屏水膜

```glsl
float wn1 = fbm2c(uv * vec2(3.1,1.7) + vec2(0.0, -uTime*0.028));
float wn2 = fbm2c(uv * vec2(8.5,4.2) + vec2(0.0, -uTime*0.050));
float film = smoothstep(0.40, 0.74, wn1*0.62 + wn2*0.38);
vec2  fOff = vec2((wn2-0.5)*0.014, -0.0022) * (0.55 + 0.9*film);
col = mix(col, texture2D(tSoft, uv + fOff).rgb * 1.05, film*0.22);
```

- 两层噪声，慢速向下漂移（0.028 / 0.050 UV/s）
- 折射偏移很小（±0.007 UV），只是让画面轻微"化开"，不糊

## 2. 竖向水痕

```glsl
float sline  = fbm2c(vec2(uv.x*34.0, uv.y*1.3 - uTime*0.06));
float streak = smoothstep(0.50,0.74,sline) * smoothstep(0.90,0.25,uv.y);
```
沿玻璃往下爬的细水痕，越靠下越淡。

## 3. 大滴摊开

`flatAmt = clamp((r - 0.018)/0.022, 0, 1)`，越大的滴横向越宽
（`q.y *= 1 + flatAmt*0.55`），不再是标准圆形。

## 4. 性能

水膜多 2 次 fbm（3 octave），60fps 不变。

## 5. 还差的

- 水膜对比度偏低，白天/夜里的可见度差别大
- 「撞击炸开」的飞溅珠仍然偏小，缺少大滴被拍碎成一片水花的状态

# Stage 25 · 撞击瞬间

## 1. 时间窗状态

每颗水珠多传一个 `uDropAge[32]`，`burst = 1 - smoothstep(0, 0.16, age)`：

| 量 | 炸开时 | 稳定时 |
|---|---|---|
| 半径 | ×1.48 | ×1.0 |
| 轮廓 | 7 / 13 次谐波径向起伏（±0.28） | 2.7 / 4.3 / 7.1 次（±0.09） |
| 扁平度 | `z` 指数 0.45 | 0.70 |
| 边缘亮度 | ×1.55 | ×1.0 |

## 2. 飞溅卫星滴

撞击时生成 3–5 颗卫星滴，带**径向初速度**：

```js
vx = cos(a) * (0.10 + rand*0.22)
vspread = sin(a) * 0.13
```

每帧衰减 `v *= (1 - 3.4*dt)`，所以它们先向外飞散、随后被水膜拖住。

## 3. QA 参数

`?dropage=0.06` 可以让测试用的水珠停在这一瞬间，方便截图核对。

## 4. 性能

32 颗滴 + 水膜 2 次 fbm，60fps。

## 5. 诚实评价

- 静止帧只能抓到某一瞬间，**动态效果需要实际跑起来看**
- 炸开的形状仍偏「花瓣」，真实水花更无规则；但已经不再是完整玻璃球

# Stage 30 · 光照重做 + 放大（最终取 5 倍）

## 1. 光照重做

原先把 SpotLight 挂在 `group` 里，group 缩放后灯的位置被放大 8~10 倍，
锥角与距离却不跟着变，所以光「打空」。

**改法**：灯全部挂到 `scene` 根节点，用世界坐标手动对准：

```js
mk(baseX + 220, 1400, baseZ + 120, baseX, 700, baseZ, 2.6e6, 0.26);  // 塔顶主光
mk(baseX - 220, 1200, baseZ + 80,  baseX, 560, baseZ, 1.6e6, 0.28);
mk(baseX + 30,  60,  baseZ + 420, baseX, 900, baseZ, 1.1e6, 0.34);   // 地面仰光
```

## 2. 放大倍数的取舍

试了三档：

| scale | 距离 | 结果 |
|---|---|---|
| 10 | 1400 m | 雾里几乎看不见，塔顶出画 |
| 8 | 1400 m | 仍然偏暗，被避雷塔抢戏 |
| **5** | **700 m** | **火箭清晰可辨，构图完整** |

雾（FogExp2）是这个取舍的核心矛盾：越远越被雾吃掉。
所以最终取 **5 倍 / 700 m**，并把雾降到 0.0030（白天）/ 0.0011（夜里）。

## 3. 细节

- 国旗（canvas 画的五星红旗）贴在芯级
- 8 台芯级喷管 + 4 台助推器喷管
- 级间黑带、整流罩分离线、4 条贴面管路
- 塔架 11 层栏杆、10 段楼梯、3 根管线
- 避雷塔 4 根

## 4. 可以调的参数

`launchSite()` 顶部三个常量：

```js
const PAD_X = 175, PAD_Z = -680;   // 位置
const SCALE = 5.0;                 // 整体倍率
```

改 SCALE 时记得同步 `FOG.density`，否则远景会被雾吃掉。

## 2. 5:30 火箭上的树影：排查结果

**先确认现象**：确实有树影落在箭体和背塔墙上。

**算一下**：5:30 太阳高度约 7°。
20 m 高的树，影子长度 = 20 / tan(7°) ≈ **163 m**。
发射场距路 168 m，禁区半径 118 m —— 最近的树在 50 m 外，

所以这不是 bug，是物理上成立的。但为什么看着"脏"：

| 因素 | 数值 | 后果 |
|---|---|---|
| 阴影相机覆盖 | ±230 × ±200 m | 460 m 摊到 4096 贴图 → **8.9 texel/m** |
| 每 texel 对应 | 11 cm | 树影变成一团团的模糊色块 |
| PCF radius | 1.2 | 再糊一层 |

三个因素叠加，远处的树影就变成了箭体上的脏斑。

**修法**：发射场所有网格 `receiveShadow = false`，但保留 `castShadow = true`。

- 火箭/塔架**仍会在地面投影**（这个是你之前要的）
- 火箭**不再接收**远处树影（脏斑消失）
- 地面硬化区仍然接收阴影，所以塔影、树影在地面上是正常的

顺手把 `shadow.radius` 从 1.2 降到 0.9，让影子更实一点。

## 3. 代价

火箭现在也不接收**塔架自身**投下的阴影（比如摆杆在箭体上的影子）。
要做到"远处不脏、近处有自阴影"，需要级联阴影（CSM）——两套阴影相机，
一套近 ±60 m 高精度给箭体/塔架，一套远给地面。成本会翻一倍多。

# Stage 38 · 阴影：8192 单级联 + 选择性接收

## 1. 先说清楚：这不是真正的 CSM

真正的 CSM（级联阴影）需要**把多套 shadow matrix 注入每个材质的 shader**，
在片元里按深度选择级联采样。这个场景有 9 套着色器（地面、草、植被、发射场、天空……），
逐套注入的回归风险很高（之前已经因为 shader 改动把天空整片搞黑过两次）。

所以我做的是**等效方案**：

| 手段 | 参数 | 效果 |
|---|---|---|
| 贴图分辨率 | 4096 → **8192** | 精度 ×2 |
| 相机范围 | ±230 → **±175 m** | 覆盖密度 ×1.3 |
| 最终精度 | 8.9 → **23.4 texel/m**（4.3 cm/texel） | 比多数游戏的 CSM 近级联（10–15 texel/m）还高 |
| PCF radius | 1.2 → **0.5** | 影子更实 |

8192 × 4 字节深度贴图 = 268 MB 显存，实测 **60 fps 不掉**。

## 2. 5:30 树影问题的真正解法

物理上树影确实会打到火箭（7° 太阳角，20 m 树 → 163 m 影子）。
8192 只是让它更清晰，但它还在。

所以加了**选择性接收**：

```js
mesh.castShadow = true;      // 继续投（地面有塔影）
mesh.receiveShadow = false;  // 不接收（箭体上不起树影）
```

这等价于「CSM 里把远级联排除在箭体之外」——视觉结果一样，但没有多套 shader 的风险。

## 3. 代价

- 火箭不接收塔架自身的投影（摆杆在箭体上的影子）
- 地面仍正常接收所有阴影（塔影、树影、栏杆影）

# Stage 47 · 海面平面反射：两次尝试后的结论

## 做法

1. 建一个 `WebGLRenderTarget`（半分辨率）+ 镜像相机
2. 镜像相机：`position.y = 2*seaY - cam.y`，`rotation.x` 取反
3. 反射 pass 里隐藏 `sea / ground / grass / emb`（自定义 shader 不吃全局裁剪面）
4. 渲染到 RT，海面 shader 用屏幕 UV 采样

## 结果：**失败**

RT 里是纯白 —— 反射相机渲染出来的内容基本只有天空。
原因有两层：

1. **全局裁剪面对自定义 ShaderMaterial 无效**，地面/草会把整个画面填满；
   隐藏它们之后，剩下的只有天空和少量树，而天空本身在白天就是白的
2. 水面在掠射角（fresnel ≈ 0.9）时几乎全是反射色，
   所以采样到白色 RT 就直接变成一片白，波浪细节被完全盖掉

## 结论

在这个场景里，**解析式天空反射（按法线反射方向取天空渐变）反而是更稳的方案**：
它保留了波浪明暗，也避免了 RT 里没有内容的问题。

真要做平面反射，前提是：
- 给地面/草/海補上 `clipping_planes` 代码块（不是隐藏，而是真裁剪）
- 或者用 SSR（屏幕空间反射），但海面在屏幕边缘会失效

这两条都不是小改动，暂时保留解析式方案。

# Stage 49 · 海面反射成功（Reflector 算法）

## 关键：斜裁剪投影矩阵

之前两次失败的核心是「直接复制主相机投影矩阵」。正确做法（three Reflector 同款）：

1. **镜像相机**：位置关于水面镜像，`up` 向量也镜像，再 `lookAt` 镜像目标
2. **斜裁剪近平面**：把近平面压到水面上，这样水面以下的几何天然被裁掉，
   不需要依赖全局 clipping（对自定义 shader 无效）
3. **投影纹理矩阵**：`texMat = bias * proj * viewInverse`，
   shader 里用 `texture2DProj(tReflect, vRefl)` 采样

```js
plane.setFromNormalAndCoplanarPoint(normal, point).applyMatrix4(cam.matrixWorldInverse);
clip.set(plane.normal.x, plane.normal.y, plane.normal.z, plane.constant);
q.x = (sign(clip.x) + pm[8]) / pm[0];
q.y = (sign(clip.y) + pm[9]) / pm[5];
q.z = -1.0;
q.w = (1.0 + pm[10]) / pm[14];
clip.multiplyScalar(2.0 / clip.dot(q));
pm[2] = clip.x; pm[6] = clip.y; pm[10] = clip.z + 1; pm[14] = clip.w;
```

效果：海面能映出塔架、电线杆、树的倒影，同时保留波浪明暗。**60 fps 不变。**

## 2. 海面反射：把「投影纹理矩阵」换成「屏幕 UV」

### 上一版为什么假
1. `_texMat` 在**斜裁剪改过投影矩阵之后**才构建 —— 而 three 的 Reflector 是先建纹理矩阵、再改投影。（顺序反了，采样坐标整体偏掉）
2. 即使顺序对，投影纹理在**贴地平线**时 `w→0`，ndc 直接飞出 [0,1]，于是整片海退回解析天空 → 一片奶白。
3. 波浪法线幅度失控：`dn` 能到 1.5，法线躺平，菲涅尔算出来只有 0.2，海面既不像水也不反光。

### 现在的做法
**镜像相机与主相机投影完全相同、位置关于水面镜像，所以水面上一像素的反射就落在同一个屏幕位置。**
于是直接用 `gl_FragCoord.xy / uRes` 采样反射 RT：

```glsl
vec2 suv = gl_FragCoord.xy / uRes;
suv += N.xz * (0.020 / (1.0 + dist * 0.012) + 0.0035);   // 法线扰动
// 5 tap 距离模糊
refl = mix(skyRef, refl, smoothstep(0.015, 0.20, R.y));   // 贴地平线退回解析天空
```

其余重写项：
- **涌浪**：4 个方向的正弦脊 + 风致各向异性（脊线垂直于风）
- **细节法线**：waternormals 三尺度滚动，按距离淡出（远处不闪）
- **吸收**：深水墨蓝 `(0.008,0.024,0.040)`，近岸青绿，夜间压暗
- **阳光/月光**：`pow(dot(N,H), mix(30,1100,rough))`，远处按距离淡出防闪烁
- **白沫**：近岸带收窄到 σ=4.5 m（原来是 16 m，整片近景都刷白），加朝岸推进的白线
- **雾/地平线**：1200–2600 m 融进雾色，去掉硬边

## 3. 渲染：TAA 降噪 + CAS 锐化

### TAA（时域抗锯齿 / 降噪）
- 每帧对投影做 **Halton(2,3) 亚像素抖动**
- 3×3 邻域包围盒把历史色夹进去（**方差截断**，防拖影）
- 用深度反投影到上一帧的 view-projection 里找历史（不是简单复制屏幕像素）
- 天空（depth≈1）历史权重 0.86，几何边缘降到 0.55
- 反射 pass / 主渲染 / 体积光共用同一份抖动矩阵，避免对不齐

效果：护栏、电线、草叶、雨丝的锯齿明显收敛，动态画面不再「沙沙响」。

### 锐化
在显示空间做**对比自适应** USM：平坦区域（天空/雾）少锐化，细节区域（沥青、岩石）多锐化，强度 0.42。比固定 USM 的过冲小很多。

# Stage 52 · 修复：路面/火箭/护栏/发射塔/树 整片消失

## 现象

打开成片，路面、火箭、发射塔、护栏、树、路灯全都不见了，天空里只剩几根**漂浮的虚线**。
把 `?refl=0`（关掉海面平面反射）就一切正常。

## 排查过程（弯路记下来，下次别再走）

| 怀疑对象 | 验证方式 | 结果 |
|---|---|---|
| 材质（clearcoat 烧白） | 运行中把 clearcoat/env/spec 全置 0 | 无变化 |
| 光照（灯太亮） | 关掉全部 DirectionalLight/Hemisphere/Ambient | 无变化 |
| 深度/遮挡（地面盖住路面） | 把地面降 3 m | 无变化 |
| 视锥剔除 | 全场 `frustumCulled = false` | 无变化 |
| 隐藏清单（反射 pass 藏物体） | `__noHideRefl` 跳过隐藏/恢复 | 无变化 |
| 阴影贴图 | 恢复 `shadowMap.autoUpdate` | 无变化 |
| TAA 拖影 | `uBlend = 0`（纯当前帧） | 塔出现了 → **误判** |
| 反射本身 | 运行时 `__forceNoRefl = true` | 无变化 |

**最后靠一次「在页面脚本执行前注入标志位」的测试定案**：
```js
// Page.addScriptToEvaluateOnNewDocument
window.__forceNoRefl = true;   // 让反射 pass 一次都别跑
```
→ 物体全部回来。而运行时再关掉反射则**没用**。

## 真因

**反射 pass 抢在主画面之前、在场景还没「暖机」的时候先渲染了一帧。**

那一帧里：
- 阴影贴图还没生成（`shadowMap.autoUpdate=false` 且 `needsUpdate` 还没置位）
- 环境反射图还没烘好

于是这批材质（路面 / 护栏 / 塔架 / 树 / 路灯）在**缺 shadow map / 缺 env** 的状态下编译出了错误的 program 变体，
之后主画面再渲染时它们就再也不出来了 —— 症状是「整片消失，只留几根漂浮虚线」（那些虚线就是塔架桁架的残影）。

## 修法

```js
// 先让主画面完整渲染两帧，再开反射
if (reflWarm < 2) reflWarm++;
if (seaObj && !NOREFL && reflWarm >= 2 && updateReflection()) { ... }
```

## 顺带纠正两条上一版的错误结论

1. **「TAA 会啃掉细结构」是误判。** 当时用 `uBlend=0` 关掉 TAA 后塔架回来了，但那是因为
   `uBlend=0` 同时绕过了被污染的 program 变体。修好暖机顺序后，TAA 开着塔架完好无损，
   所以 **TAA 重新默认开启**（`?taa=0` 可关）。
2. **「反射 pass 里看不见东西」也不是正交性问题**，而是同样的暖机问题。

| 水/积水 | 地面 shader 里一条"水位场"：puddle / soak / damp 三段，**粗糙度直接映射成反射的 mip-LOD**，近处镜面、远处只有一层纵向拉长的光泽 | 平面反射 + 固定 5 tap 模糊 |
| 色调 | AgX（three r180 自带实现） | ACES |
| 曝光 | `tAdapt` 纹理 + `pow(uKey/a, 0.85)` 自适应 | 定值 1.14 |

## 2. 这一轮真移植了什么

### ✅ ① 太阳辉光收窄（最大的"光影怪"来源）

```glsl
// 旧：半宽约 60°，整个天穹都在发光 → 没有明暗对比，影子看不见
col += vec3(1.0,0.52,0.26) * exp(-pow(rr,2.0) * 0.55) * 0.30 * uSunDisk;
col += vec3(1.0,0.44,0.16) * exp(-ang * 3.2) * 0.55 * uSunDisk;
// 新：aureole 收到 ~7°，日面外围单独一条窄光
col += vec3(1.0,0.52,0.26) * exp(-pow(rr,2.0) * 9.0) * 0.42 * uSunDisk;
col += vec3(1.0,0.44,0.16) * exp(-ang * 26.0) * 1.10 * uSunDisk;
```

顺带把天空的地平线带收窄（`exp(-hz*7)` → `exp(-hz*13)`）、白天冷暖色压深，
云层覆盖 0.54–0.64 → 0.40–0.50、不透明度 0.62–0.70 → 0.44–0.52。

**结果**：白天从"一张白纸"变成有天光层次的蓝天＋云，护栏/灯杆终于有影子了。

### ✅ ② 光比：影子被环境光淹没了

诊断过程：把 Hemisphere/Ambient 关掉后，**护栏的影子立刻显形**——所以阴影一直在渲染，只是被环境光冲淡了。

```js
hemi.intensity       lerp(0.42, 2.6, lightW) → lerp(0.26, 0.92, lightW)
sunLight.intensity   3.4 + 3.4·s^0.55       → 5.2 + 6.4·s^0.55
environmentIntensity 0.18 + 0.30·lightW     → 0.10 + 0.15·lightW
```

### ✅ ③ SSAO（照它的 `X6`/`Y6` 两段改写）

半分辨率深度（`texelFetch` 2×2 抽点）→ 反投影求视空间法线 → 12 tap 半球采样 →
`max(R²-|v|²)³ · max((vn-bias)/|v|², 0)` → 4 向模糊 → 合成时乘进场景色。

踩的坑：半径 0.85 m + UV 上限 0.16 在掠射地面上会采样到几米外，`vv` 变得极小、
`vn` 噪声被放大 → 近处 AO 直接 0.03（死黑）。改成半径 0.38 m、UV 上限 0.055、
bias 随 `z0` 增长，并给 AO 下限 0.42 兜底。

### ✅ ④ 水面反射改成 mip-LOD 采样

```glsl
// 旧：固定 5 tap
// 新：反射 RT 开 mipmap，按距离 + 掠射角选 LOD
float graz = pow(1.0 - clamp(V.y, 0.0, 1.0), 4.0);
float lod = clamp(log2(1.0 + dist * 0.30) + graz * 1.2 - 0.4, 0.0, 6.0);
refl = texture2D(tReflect, suv, lod).rgb;
```
一次采样代替五次，近处锐、远处自然发糊（原来是均匀糊）。

### ⏸ ⑤ AgX 与 PCSS：接了但没默认开

- **AgX** 已按 three r180 的原始实现搬进 comp（`uTone` 切换）。实测在**我们这个雾重、环境光强的场景里偏灰**
  （mean 129 / p95 198，ACES 是 144 / 225），所以默认仍用 ACES，留着 `uTone=1` 可选。
- **PCSS** 需要改 `sampler2DShadow` 的读取方式（它的实现用的是 RGBADepth 打包），
  本轮没动，只在 report 里记下方案。

|---|---|

| 曝光 | 高光溢出 0.00%、死黑 0.02% |

# Stage 54 · 天空重写 + 自适应曝光（Saltline 移植第二弹）

## 1. 把「5 层平面云」换成「一整片云海 + 太阳洞」

原来的天空是 5 张 9000/7000/5200/3800/2800 米的平面云叠着，
每层各自 fbm、各自 alpha，叠起来 ≈ 一张白纸：没有云形、没有体积、没有方向光。

照 Saltline 的 `SALTLINE_SKY` 改成**在天空 shader 里画**：

```glsl
// 视线打到云层平面上的投影（越贴地平线越密，远处自然收束）
vec2 cuv = d.xz / (h + 0.085) * vec2(0.62, 0.95);
float warp = fbm2(q * 0.42 + 7.1);
vec2  qq   = q + (warp - 0.5) * 1.15;
float body = fbm2(qq * 1.05 + 3.3) * 0.80 + fbm2(q * 0.17 + 3.7) * 0.34;

// ① 朝太阳让开一条"燃烧的空隙"
float edge = mix(0.035, 0.30, pow(tsun, 1.6));
cov *= smoothstep(edge - 0.035, edge + 0.12, h + rag * (0.35 + tsun));

// ② 太阳处烧一个洞（云永远不遮住太阳本体）
float hole = smoothstep(0.972, 0.9985, mu + (dens - 0.5) * 0.012);
cov *= 1.0 - 0.93 * hole;

// ③ 云底自阴影：朝太阳方向的密度梯度 = 云的立体感
float densS  = fbm2(qq + sd2 * 0.22);
float relief = clamp((dens - densS) * 4.5 + 0.5, 0.0, 1.0);
```

配色分两档：
- **低太阳**（金色时刻）→ 云底被烧成暖色，`warmC` 按 `pow(1 - sunDir.y, 1.6)` 放大
- **高太阳**（正午）→ 换成白亮的积云 `litCloud`，不再发粉

夜里 `cov *= mix(0.16, 1.0, dayC)`：云变薄，银河和星星还能透出来。

原来那 5 层平面云保留 1 层（opacity 0.10）做视差，避免"死板"。

## 2. 自适应曝光（照 Saltline 的 `tAdapt`）

三段：`8×8 对数亮度` → `1×1 时间平滑` → comp 里算 EV。

```glsl
// lum pass：5×5 采样取平均后存 log2
gl_FragColor = vec4(log2(max(acc, 1e-4)), 0.0, 0.0, 1.0);
// adapt pass：64 texel 平均 → 指数平滑（rate 0.12）
float cur = mix(prev, exp2(avgLog), uRate);
// comp：
float evAuto = clamp(pow(uKey / max(adaptLum, 1e-4), 0.85), uMinE, uMaxE);
```

**参数要收着用**：`uKey 0.22 / uMinE 0.88 / uMaxE 1.12`。
放开到 Saltline 那种 `0.55–2.6` 会让夜景直接提亮 60%（这个场景的夜晚本来就该暗）。

# Stage 55 · 收尾三件事：叶片透光 / PCSS / 地面脏化

## 1. 叶片透光（原来逆光是一片褐色团块）

卡片树用的是 `MeshStandardMaterial` + `onBeforeCompile`（风摆）。
`MeshStandardMaterial` 没有透射模型，逆光时叶背完全拿不到光，于是整棵树只剩一团褐色。

在 `#include <lights_fragment_end>` 后面加一项**背光透射**：

```glsl
#if NUM_DIR_LIGHTS > 0
{
  vec3 Vv = normalize(vViewPosition);            // 表面 → 相机（视图空间）
  vec3 Lv = directionalLights[0].direction;      // 表面 → 太阳（视图空间）
  float back = pow(clamp(dot(Vv, -Lv), 0.0, 1.0), 2.6);   // 逆光程度
  reflectedLight.directDiffuse += diffuseColor.rgb * uTransTint * back * uTransAmt;
}
#endif
```

- `uTransTint = vec3(1.15, 1.02, 0.52)`：阳光穿过叶子会偏黄绿
- `uTransAmt = 0.85`
- 用的是 `directionalLights[0]`，所以**不需要额外传太阳方向**，视图空间里天然一致

效果：逆光下树冠是通透的绿，而不是一片褐色剪影。

## 2. PCSS 软阴影（改写 three r185 的 getShadow）

three 的 `shadowmap_pars_fragment` 里，PCF 版 `getShadow` 是 9 tap 固定半径。
直接在 `T.ShaderChunk` 上做字符串替换，换成 **16 tap Vogel 圆盘 + IGN 旋转**：

```js
const i = src.indexOf('float getShadow( sampler2DShadow');
// 括号配对找出函数体，整段替换
T.ShaderChunk[key] = src.slice(0, i) + repl + src.slice(end);
```

```glsl
float pen = shadowRadius * ( 0.85 + 0.15 * clamp( distW * 0.02, 0.0, 1.0 ) );
float radius = pen * texelSize.x;
float phi = interleavedGradientNoise( gl_FragCoord.xy ) * PI2;
for ( int k = 0; k < 16; k ++ )
  sum += texture( shadowMap, vec3( shadowCoord.xy + vogelDiskSample( k, 16, phi ) * radius, shadowCoord.z ) );
```

配合 `sunLight.shadow.radius = 3.6`（原来 0.5）。

**注意**：`shadowCoord.xyz /= shadowCoord.w` 会把 w 变成 1，所以要在除之前把 `w` 存下来。

> 真正完整的 PCSS 需要 blocker search 估半影，但那要能读到原始深度；
> three 的阴影贴图是 `sampler2DShadow`（比较采样器），读不出深度。
> Saltline 读的是 RGBADepth 打包纹理，所以它能做。
> 想上完整 PCSS 得另挂一张 depth RT —— 本轮先用"更宽核 + 抖动"拿到 80% 的观感。

## 3. 中景地面脏化（原来是一片均匀土黄）

地面 shader 里补一层**大尺度**分区（原来是 9.5 / 29 / 2.4 m 三个尺度，缺 45–180 m 这一档）：

```glsl
float mL = fbm(p * 0.0055 + 91.0);          // ~180 m 土质分区
float mM = fbm(p * 0.022  + 51.0);          // ~45 m 斑块
float patch = smoothstep(0.32, 0.78, mL * 0.62 + mM * 0.38);
soil = mix(soil * vec3(0.80, 0.82, 0.86), soil * vec3(1.16, 1.06, 0.88), patch);
float gravel = smoothstep(0.58, 0.86, fbm(p * 0.13 + 17.0));   // 砾石带
float dryMac = smoothstep(0.45, 0.80, fbm(p * 0.010 + 131.0));  // 干湿大区
```

# Stage 56 · 事故：地面整块消失（左边"堤坝高过栏杆"、右边"土地变成水面"）

## 现象

- 右边本该是土地，结果整片是水（树像长在水里）
- 左边护坡看起来高过护栏

## 真因：`patch` 是 GLSL 保留字

Stage 55 给地面加大尺度脏化时写了：

```glsl
float patch = smoothstep(...);   // ✗ patch 在 GLSL 里是细分着色器的保留字
```

→ 整个地面 shader **编译失败** → 地面 mesh 什么都不画 → 下面 14 米处的海面透出来。

所以"右边是水"不是水出了问题，是**土地根本没渲染**；"左边堤坝高"是因为地面没了，
护坡的岩石坡面直接露在护栏后面，看上去像一道墙。

## 修复

```glsl
float soilPatch = smoothstep(...);   // ✓ 改名
```

顺带把地面左边缘从 x=-19 收回到 **x=-12（正好接护坡堤顶）**——
原来那 7 米平地盖在护坡上方，从路上根本看不到岩石坡面。

## 教训

1. **GLSL 保留字清单**（踩过的）：`patch`、`input`、`output`、`filter`、`active`、`common`、
   `partition`、`resource`、`sample`、`smooth`、`superp`、`template`、`this`
2. **改完 shader 第一件事是看 console**，不是看画面。
   这次画面"看起来还行"（一片灰白能当成水面），于是一路带到了交付。
   `tools/errcheck.js` 一条命令就能看到 `ERROR: 0:110: 'patch' : Illegal use of reserved word`。

上一版是「点一下整箭散开」。现在按新要求改成**点哪个部件，哪个部件自己缓缓升起**：

```js
focus = (focus === 该部件) ? null : 该部件;   // 再点一次收回
p.t += (target - p.t) * min(1, dt * 1.15);   // 时间常数 ≈ 0.9 s，"缓缓"
```

升起的同时：
- **外壳变半透明**（opacity 1 → 0.22，`depthWrite` 在前 35% 保持开启避免闪烁）
- **内部结构显形**（`inner` Group 由隐藏切到可见）
- 塔架/发射平台同步淡出到 28%
- 只在当前部件旁显示一块中文标签

## 2. 内部结构（按真实布局建模）

| 部件 | 内部 |
|---|---|
| 整流罩 | 卫星适配器锥、卫星本体、太阳翼、分离推杆 |

# Stage 60 · 修比例 + 补内部机械 + 一键合体

## 1. 「一进去火箭就解体」的真因

不是加载状态错 —— 冷启动探针确认 `focus=none`、所有部件 `t=0`、位置在原位。

真因是**首屏那句「点击画面任意处开始播放音乐」**：用户第一次点击（为了起播）
正好落在火箭上，于是触发了一个部件的升起 —— 看上去就像"一进来就解体"。

修法：交互加 1.4 s 首屏保护窗

```js
const PAGE_T0 = performance.now();
if (performance.now() - PAGE_T0 < 1400) return;   // 首帧那一下是起播音乐
```

# Stage 61 · 真因找到：部件几何没扣掉 base（火箭一直是"散"的）

## 1. 「一进去就解体 / 一键合体也是分开的」——同一个 bug

上一轮我把原因猜成"首屏点击起播音乐时点到火箭"，判断错了。

真因在 `addShell` / `addInner`：几何是按**绝对坐标**建的，而部件 Group 又被放在 `base` 位置，
于是每个部件被**偏移了两次**：

```
芯级 Group.y = 9，几何圆心 y = 24.5  →  实际世界 y = 33.5（应为 24.5）
整流罩 Group.y = 52.5，几何 y = 57.5  →  实际 110
```

所以火箭一直是被拉成几十米的"散件"，点不点都一样。

修法：入库前先把几何换回部件局部坐标

```js
function addShell(rec, geo, mat) {
  geo.translate(-rec.base.x, -rec.base.y, -rec.base.z);   // ★ 关键一行
  ...
}
```

修完实测：`bbox y = 7.8..68.3`（全长 60.5 m 的连续箭体），一键合体后 7 个部件全部 `t=0`。

## 2. 塔架改成开放桁架（一直能看见内部）

服务塔原来是几面**实心墙板**（`boxAt(... BW*2, TH, 0.8)`）。现在整面墙换成：

- 背面 11 根立柱（间距 2.9 m）+ 侧向 3 根
- 13 层横梁 + 每层一组斜撑
- 楼板、栏杆、斜梯、设备柜保留

于是从任何角度都能直接看到**楼层、栏杆、内部设备**，不再需要靠淡出才看得见。

## 3. 助推-芯级连接（照片里是小接头，不是长杆）

原来用两根 φ0.42 的横杆连着，很丑。改成：

```js
for (const dy of [6.0, 14.0, 20.5])
  // 芯级表面上一块 0.9×0.85×0.75 的支座 + 一根斜撑
```

## 4. 助推头锥改成「半圆锥 + 竖切面朝芯级」

```js
const g = new T.LatheGeometry(pts, 18, 0, Math.PI);   // 只旋转半圈
g.rotateY(-a);                                        // 切面朝向芯级
g.translate(bx, Y_CORE + H_BOOST, bz);
```

再用 `ShapeGeometry` 按同一条轮廓做一个**竖切面封板**补上，避免半锥背面漏光。
方向推导：Lathe 半圈占 `x>0`，平法线为 `-X`；要把 `-X` 转到「指向芯级」的方向，
即让 `+X` 对准 `(cos a, sin a)`，绕 Y 旋转 `-a`。

## 5. 验收

| 项 | 值 |
|---|---|
| 帧率 | 60.2 fps |
| 冷启动 | bbox 7.8–68.3 m 连续箭体，focus=none |
| 一键合体 | 7 部件全部 t=0（实测） |
| 塔架 | 开放桁架，始终可见内部楼层 |

# Stage 62 · 箭体纹路收敛 + 拆解防重叠 + 塔臂外摆 90°

## 1. 箭体纹路按照片收敛

之前箭体上堆了 4 道亮银环箍、2 个大贴片，比照片脏得多。改：

| 去掉 | 保留 |
|---|---|
| 芯级 4 道 `steelLight` 环箍 | 2 道 0.075 m 的 `M.seam` 细对接缝 |
| 二级 2 道亮箍 | 1 道细缝 |
| 助推 3 道亮箍 | 1 道细缝 |
| 芯级上的 CASC 标 | CASC 移到**二级**（照片里就在整流罩下方）|
| 方格 4×4 | **8×8**（照片里的方格更密）|

贴图的黑底问题也一起修了：`MeshStandardMaterial` 加了 `alphaTest: 0.45`，
否则 canvas 的透明区在混合时会发黑（之前「中国航天」后面有一块黑方块）。

## 2. 拆解重叠：二级钻进整流罩

原因：二级的升起量 +14 m，而整流罩在它上方 12.5 m 处不动 → 二级头顶穿进整流罩。

修法两条：
1. 二级升起量 14 → **24 m**
2. **上方的部件被顶起来**：

```js
if (u.focus && p.base.y > u.focus.base.y)
  lift = u.focus.off.y * fe;      // 聚焦部件的升起量传给上方所有部件
```

实测：二级 `y=64.0`、顶面 76.5；整流罩被顶到 **76.5** —— 正好相切，不再穿模。

## 3. 塔臂外摆 90°（发射流程第一步）

原来的侧塔是**静态合并几何**，没法动。现在每侧重建为一个 `Group`，几何先换到**铰点局部坐标**：

```js
pivot.position.set(cx, 0, hz);              // hz = -5.5，塔臂后缘
P = (g) => { g.translate(-cx, 0, -hz); bp.push(g); };   // 换坐标
pivot.add(new T.Mesh(mergeAll(bp), blueMat));
```

旋转方向：右臂 `rotation.y = +90°`（+Z 端转向 +X，即向外张开），左臂 `-90°`。

铰接机构另做：φ1.15 竖轴 + 三个 φ1.7 法兰 + 上下各两根斜撑。
塔臂也往外挪了 2 m（±17 → ±19）、加宽到 8 m，摆杆延长到 13 m。

右上角按钮「塔架张开 / 塔架合拢」切换，1.5 s 时间常数平滑过渡。

## 4. 下一步（用户已定的发射流程）

1. 塔臂张开 90°（本阶段已做）
2. 底座把火箭向外平移
3. 点火发射
